# 0002. Unified Workers-First Architecture with Cloudflare Assets Binding

- **Status:** Accepted
- **Date:** 2026-03-31
- **Deciders:** Autonomous Architect (Archie) / Repository Analysis

## Context

Cloudflare deprecated legacy Pages functions and separate Pages site bindings in favor of a single unified Workers-First model (`wrangler.jsonc` + `assets`). This project requires static pre-rendering with Edge dynamic routing capabilities (such as Workers AI, Cloudflare KV, and custom header transformations) while delivering static assets directly via Cloudflare's edge CDN asset binding (`ASSETS`).

## Decision

Adopt the unified Workers-First binding pattern (`wrangler.jsonc`) using `./src/cloudflare-worker.ts` as the primary Cloudflare Worker entry point and `./dist` configured under `assets.directory` with the `ASSETS` binding. Static HTML files generated by Astro are served by the `ASSETS` fetcher, while custom worker logic intercepts fallback routes (such as custom 404 pages or edge endpoints).

## Consequences & Tradeoffs

- **Positive:** Zero latency static asset delivery via Cloudflare's global edge network, coupled with full programmatic access to Cloudflare Workers APIs (KV, Workers AI, environment bindings) in worker code. Eliminates legacy Cloudflare Pages deployment ambiguity.
- **Negative / Risks:** Local development and testing require `wrangler` or proper worker environment simulation for Cloudflare bindings. Non-worker Node environments (such as Render) require stubbing (`src/env/cloudflare-workers.node.ts`).
- **Adoption Readiness:** Already fully integrated into `wrangler.jsonc`, `astro.config.mjs`, and `src/cloudflare-worker.ts`. Codifying this pattern ensures no agent attempts migration back to deprecated Cloudflare Pages configurations.

## Directives for AI Agents

- **Do:** Maintain `wrangler.jsonc` as the single source of truth for Cloudflare deployment configuration.
- **Do:** Ensure static build outputs target `./dist` and route static asset fetches through `env.ASSETS`.
- **Do:** Run `npm run generate-types` (`wrangler types`) whenever updating `wrangler.jsonc` bindings.
- **Don't:** Introduce legacy Cloudflare Pages configuration files (`_routes.json`, `_headers`, `_redirects` in Pages format) or Cloudflare Pages build steps.
- **Don't:** Remove or bypass the `ASSETS` binding in `wrangler.jsonc`.
