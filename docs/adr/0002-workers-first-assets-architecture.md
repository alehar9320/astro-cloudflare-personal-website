# 0002. Unified Workers-First Architecture with Cloudflare Assets

- **Status:** Accepted
- **Date:** 2026-03-30
- **Deciders:** Autonomous Architect (Archie) / Repository Analysis

## Context

The repository previously relied on Cloudflare Pages or hybrid hosting patterns. Cloudflare updated its edge deployment primitives to Cloudflare Workers + Assets, unifying dynamic route handling (Workers) and static asset hosting (`assets` binding in `wrangler.jsonc`) under a single Workers runtime model.

## Decision

Adopt Cloudflare Workers + Assets (`wrangler.jsonc`) as the standard production runtime and deployment target for this personal portfolio. Static output generated by Astro is bound and served via Cloudflare's edge Assets feature while dynamic worker logic (e.g. `src/cloudflare-worker.ts`) handles API routes, telemetry, and chat stream processing.

## Consequences & Tradeoffs

- **Positive:** Unifies static content delivery and dynamic edge functions into a single worker configuration (`wrangler.jsonc`), eliminating Cloudflare Pages build configuration mismatches and providing full access to Worker KV/Bindings.
- **Negative / Risks:** Local development requires Wrangler simulation/types (`npx wrangler types`) and strict environment variable handling via `.dev.vars` / Worker bindings rather than standard Node runtime globals.
- **Adoption Readiness:** Already implemented and operational in `wrangler.jsonc`, `astro.config.mjs`, and `src/cloudflare-worker.ts`.

## Directives for AI Agents

- **Do:** Use `wrangler.jsonc` as the canonical Cloudflare deployment configuration.
- **Do:** Ensure Astro output configuration remains aligned with Cloudflare Workers + Assets bindings.
- **Don't:** Introduce legacy Cloudflare Pages configuration files (`_routes.json`, `functions/` directory) or alter Wrangler bindings without verifying Worker Assets compatibility.
- **Don't:** Add parallel production deployment workflows or bypass Cloudflare Git auto-deploy integration on `main`.
